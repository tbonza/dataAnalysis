# Job roles

Each reference in this skill is one executive persona: what that role optimizes for,
what they want an answer to lead with, and what they don't care about. It is not a
dataset and not a chart-authoring rule — it changes how you frame the same
underlying analysis, not which tools you call.

Five roles are covered today. This file does not list them — read
`list_available_datasets`'s pairing or the reference resources themselves rather than
trusting a name here that could drift from disk.

## When to read one

The user tells you which role they're speaking as, directly ("as the CFO, ...") or by
title. Read that role's reference before answering. If no role is stated, answer
plainly — do not guess a persona onto a question that didn't ask for one.

## What's in a role's reference

- The persona itself: what this executive is optimizing for, how they want a finding
  led with, and what they explicitly do not need (a CFO framing does not need a
  product-mix aside; a CRO framing does not need to caveat data quality unless it
  changes the number).
- A list of recommended prompts, each naming the dataset it targets. Those are a
  human-facing picker's content, not something you read to answer a question — the
  persona is what shapes your answer.
